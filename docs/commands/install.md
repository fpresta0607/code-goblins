# cfo install

`cfo install [--projects-root <dir>] [--dev-drive on\|off] [--uninstall]`

Wire a CFO home into the machine so `cfo` runs from any folder: `CFO_HOME` and PATH at user scope.
It writes no CFO hook into the user's `~/.claude/settings.json`: a Claude Code CFO's terminal starts with its hooks ([the CFO's own session](../contract/supervision.md#the-cfos-own-session)), so a session he opens himself runs none of them and is never supervised, guarded or woken.
Where a build before 2026-10 merged them into that file, where every Claude Code session of the user ran them, it takes them out (his own hooks are kept, the file is backed up first).
In the same write it adds allow rules for the commands that only put an item in front of the Supreme Overlord in the Command Center and run no command of their caller's, `Bash(cfo <command> *)` and `PowerShell(cfo <command> *)` for `question`, `run-request`, `review`, `present`, `deliver` and `auth request`, because Claude Code's auto mode resolves such a narrow rule before its classifier, unless `autoMode.classifyAllShell` is on, and the classifier otherwise can refuse filing a card and leave him nothing to see.
Filing a run item runs nothing: its command runs only once Run is pressed for it.
The only programs these commands start are fixed ones, lavish-axi to serve a `cfo review` page and git to check that a `cfo auth request` env file is ignored, and each refuses a caller that is neither the registered CFO nor a goblin naming its own task; the rules sit in the user's settings, so they hold in every Claude Code session of the user.
`cfo answer` gets no rule: it types the CFO's decision into a goblin's terminal, which the classifier keeps judging as it judges `cfo send`.
A rule matches the command as written, so run these as `cfo <command> ...`, as this contract writes them, never by the binary's path.
A rule the user already has, written with `:*` or ` *`, counts as there; the rules it added are recorded beside the file in `settings.json.cfo-install.rules`, and `--uninstall` removes exactly those.
The rules are the Supreme Overlord's to add, through his install or by hand: a CFO that finds them missing gives him `cfo doctor`'s line rather than adding them, since no agent widens its own permissions.
From any folder, a code-goblins checkout included, the home is `%LOCALAPPDATA%\CodeGoblins`, unless another home is already in use (below), set up from the binary itself, because the folder it runs from never decides the home: this contract and the docs it links to, the default `config/pipeline.json` and `data/routing.json` (written only where missing, so a tuned policy is kept), the layout [The CFO home](../contract/home.md#the-cfo-home) describes, the binary as `bin\cfo.exe` and `bin\goblins.exe` with `bin` on PATH, the bundled skills as one copy in `~\.agents\skills` with a junction to each from Claude Code's skills folder, `state\harnesses.json` naming where each harness keeps its configuration and skills, and a `.cfo-home` marker that makes the folder a home; nothing in a harness folder that Code Goblins did not put there is changed.
A re-run brings the contract, skills and binary up to date, moves the binaries an older install kept at the home's top into `bin`, keeping `cfo.exe` and `goblins.exe` there too, brought up to this build, since sessions started before run them by that path, and removes the files an older binary wrote that this one no longer ships (the marker lists them; a file you added is never touched).
Where `CFO_HOME` names another folder that holds a fleet's state, such as a checkout an older build made its home, it keeps that home and says so in a `Note:` line: it puts the binary in its `bin`, writes no contract into a checkout, whose files git tracks, but marks it as the home in use with the `.cfo-home` git ignores, never touches its state, data or worktrees, and restarts a supervisor running there on the new build as `cfo update` does, giving the board back to the build before if the new one does not serve; `cfo home move` moves that fleet when you choose.
A `CFO_HOME` naming a folder with no state is taken over, and that folder leaves PATH.
It also makes Windows start Code Goblins at login, in the tray, which after a restart brings back the CFO and the goblins that were working, unless Start at login was turned off; `--start-at-login off` or `on` sets that choice, which the home keeps in `state\start-at-login` and the board's switch and the window's tray change too.
`--projects-root <dir>` records the folder that holds your checkouts as `CFO_PROJECTS_ROOT`, beside `CFO_HOME` at user scope and never in this repository, which is what lets `--project` take a bare name; a plain re-install keeps whatever is recorded.
Idempotent.
It adds Code Goblins to Windows' Installed apps, whose Uninstall opens the desktop window's uninstall, and `--uninstall` runs [cfo uninstall](uninstall.md).

# goblins install

`goblins install [--projects-root <dir>] [--dev-drive on\|off] [--uninstall]`

Wire a CEO home into the machine so `goblins` runs from any folder: `GOBLINS_HOME` and PATH at user scope.
It writes no CEO hook into the user's `~/.claude/settings.json`: a Claude Code CEO's terminal starts with its hooks ([the CEO's own session](../contract/supervision.md#the-ceos-own-session)), so a session he opens himself runs none of them and is never supervised, guarded or woken.
Where a build before 2026-10 merged them into that file, where every Claude Code session of the user ran them, it takes them out (his own hooks are kept, the file is backed up first).
In the same write it adds allow rules for the commands that only put an item in front of the Supreme Overlord in the Command Center and run no command of their caller's, `Bash(goblins <command> *)` and `PowerShell(goblins <command> *)` for `question`, `run-request`, `review`, `present`, `deliver` and `auth request`, because Claude Code's auto mode resolves such a narrow rule before its classifier, unless `autoMode.classifyAllShell` is on, and the classifier otherwise can refuse filing a card and leave him nothing to see.
Filing a run item runs nothing: its command runs only once Run is pressed for it.
The only programs these commands start are fixed ones, lavish-axi to serve a `goblins review` page and git to check that a `goblins auth request` env file is ignored, and each refuses a caller that is neither the registered CEO nor a goblin naming its own task; the rules sit in the user's settings, so they hold in every Claude Code session of the user.
`goblins answer` gets no rule: it types the CEO's decision into a goblin's terminal, which the classifier keeps judging as it judges `goblins send`.
A rule matches the command as written, so run these as `goblins <command> ...`, as this contract writes them, never by the binary's path.
A rule the user already has, written with `:*` or ` *`, counts as there; the rules it added are recorded beside the file in `settings.json.ceo-install.rules`, and `--uninstall` removes exactly those.
The rules are the Supreme Overlord's to add, through his install or by hand: a CEO that finds them missing gives him `goblins doctor`'s line rather than adding them, since no agent widens its own permissions.
From any folder, a code-goblins checkout included, the home is `%LOCALAPPDATA%\CodeGoblins`, unless another home is already in use (below), set up from the binary itself, because the folder it runs from never decides the home: this contract and the docs it links to, the default `config/pipeline.json` and `data/routing.json` (written only where missing, so a tuned policy is kept), the layout [The CEO home](../contract/home.md#the-ceo-home) describes, the binary as `bin\goblins.exe` with `bin` on PATH, the bundled skills as one copy in `~\.agents\skills` with a junction to each from Claude Code's skills folder, `state\harnesses.json` naming where each harness keeps its configuration and skills, and a `.ceo-home` marker that makes the folder a home; nothing in a harness folder that Code Goblins did not put there is changed.
A re-run brings the contract, skills and binary up to date, moves the binaries an older install kept at the home's top into `bin`, keeping `goblins.exe` there too, brought up to this build, since sessions started before run them by that path, and removes the files an older binary wrote that this one no longer ships (the marker lists them; a file you added is never touched).
In a home whose heavy folders are on a Dev Drive it puts the gate's home there, as [goblins dev-drive move](dev-drive.md) carries it, before `install.ps1` installs no-mistakes and starts its daemon: a gate with no home yet is named `no-mistakes` in the Dev Drive folder by `NM_HOME` from the start, which `install.ps1` gives its own no-mistakes too, and one elsewhere moves there unless a gate run is in flight, which it does not wait for: a `Note:` line says so, and the board's Dev Drive panel offers the move.
Each run, an update's included, also sets up the [crawler connector](../crawler.md) every goblin carries, as [goblins crawler setup](crawler/setup.md) does, and leaves one already this build's as it is; one it cannot set up, as on a machine without Node.js or one whose `npm ci` runs past two minutes, which is stopped with every process it started, never fails the install, and a `Note:` line says goblins go without it until `goblins crawler setup` succeeds.
Where `GOBLINS_HOME` names another folder that holds a fleet's state, such as a checkout an older build made its home, it keeps that home and says so in a `Note:` line: it puts the binary in its `bin`, writes no contract into a checkout, whose files git tracks, but marks it as the home in use with the `.ceo-home` git ignores, never touches its state, data or worktrees, and restarts a supervisor running there on the new build as `goblins update` does, giving the board back to the build before if the new one does not serve; `goblins home move` moves that fleet when you choose.
A `GOBLINS_HOME` naming a folder with no state is taken over, and that folder leaves PATH.
It also makes Windows start Code Goblins at login, in the tray, which after a restart brings back the CEO and the goblins that were working, unless Start at login was turned off; `--start-at-login off` or `on` sets that choice, which the home keeps in `state\start-at-login` and the board's switch and the window's tray change too.
`--projects-root <dir>` records the folder that holds your checkouts as `GOBLINS_PROJECTS_ROOT`, beside `GOBLINS_HOME` at user scope and never in this repository, which is what lets `--project` take a bare name; a plain re-install keeps whatever is recorded.
Idempotent.
It adds Code Goblins to Windows' Installed apps, whose Uninstall opens the desktop window's uninstall, and `--uninstall` runs [goblins uninstall](uninstall.md).

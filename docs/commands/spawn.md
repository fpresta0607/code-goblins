# cfo spawn

`cfo spawn <id> --project <p> --brief <b> [--harness <h>] [--mode <m>] [--model <m>] [--effort <e>] [--class <c>] [--title "<short title>"] [--yolo] [--overlap-ok "<why>"]`

Dispatch one goblin (ship task).
Resolve delivery from the project's `delivery.posture` and the brief's explicit surface, risk and reason, as [Delivery intake](../contract/delivery.md#delivery-intake) specifies.
Missing or uncertain configuration selects no-mistakes.
An explicit `--mode` cannot silently narrow the selected rigor; a concrete Overlord exception is recorded with `--delivery-exception "<authority and reason>"`.
The selected mode, posture, reason and required proof are frozen before launch in `delivery.json`, bound by the task record's hash.
The task keeps the short title it is dispatched under, for the board and for its ticket: the one given with `--title` (one line, at most 100 characters), else the title of its row under Queued in the backlog, cut at a word to 100 characters and without a harness named at its end such as `; Claude Code`; with neither it is named by its id, never by its brief's words.
Into a repository other people work in it first reads what they have in flight (one `cfo tickets` read against the brief): when a teammate's pull request or branch changes a file in the brief's area, or a teammate's issue matches it, it prints each overlap, starts nothing and exits 1, and starts only when repeated with `--overlap-ok "<why>"`; the reason is written to the task's status log as an `overlap-accepted:` record with what it overlaps, which is the CFO's word and never read as the task's own report, and the supervisor puts it on the task's ticket.
The fleet's own pull requests and issues never stop a spawn, nor does a bot's work, nor the issues the task itself is for (the ones its brief names to take up or its ticket is on), unless someone else has one of them: an issue its brief names that is assigned to another account, or carries a `cfo:` state label without being assigned to the Overlord, which is how another person's fleet holds it, is an overlap that stops the spawn like any other, since the task's claim of it would be refused; a GitHub read that fails, or does not finish within 30 seconds, starts the task unchecked and says so, because a dispatch never waits on GitHub; a read that stopped short of something (a pull request's or branch's changed files, a cap, the deadline ending its later calls) still refuses on the overlaps it did find and otherwise starts the task, with one stderr line saying the check was incomplete, how many things were not read and the first three of them in `cfo tickets`' words, and a project with no GitHub repository starts without a word.
Then every goblin starts in a native terminal of its own (see docs/native-board.md).
Without `--harness` the brief is classified and routed through the lane table in `data/routing.json` (a project manifest's `routing` block overrides it for that project): quota-axi headroom is read first, a lane whose provider or model scope is `exhausted_now` is passed over for the next usable one, and a spawn with no usable lane is refused with the reset time; a missing, stale, or unparseable quota-axi is no evidence and the spawn routes as configured saying the check was skipped.
One `routed lane=... class=... risk=... source=...` line follows `spawned ...`, naming the wanted lane when quota moved it.
Explicit `--harness`, `--model`, and `--effort` win and are reported as `source=--harness flag`; `--auto` is an alias for the default.
A Claude goblin whose flag or lane names no model runs `claude-opus-5-5`, and `cfo switch` to Claude does the same.
Reads the services the brief's Authentication section names and runs the auth preflight for those before anything is built: a name the project's manifest does not declare refuses the dispatch, and it **refuses to dispatch** while a blocking service among them is red, printing the exact `cfo auth store` command per fault (`--yolo` overrides a red service and records the override).
On a clean preflight it injects the credentials of those services into the goblin's terminal before the harness starts, and of no other, names them in the task's record, appends a one-line summary right after the `spawned ...` line and, where it withheld anything, one `auth: withheld ...` line naming each withheld service and the `cfo auth grant` that gives one ([Credentials by need](../contract/authentication.md#credentials-by-need)).
It also prints a one-line outcome-split speed hint for the chosen harness when telemetry exists.
A `no-mistakes` task freezes its `--class` review budget from `config/pipeline.json` at spawn.
Where that policy is version 6, under which a gate runs on its task's own harness, a task whose harness no gate can prove is refused, since no gate can run on it

# cfo tickets

`cfo tickets <project> [--brief <file>] [--files <paths>] [--json]`

Read-only report of what others have in flight in the project's GitHub repository, read through `gh` with one GraphQL query (about three points of the hourly budget every goblin, gate and the CFO share), more pages of it only where a list has them, the full file list of each pull request that changes more than 100 files, and one compare for each teammate branch no pull request heads (at most 30).
It says whether the repository is collaborative: a person other than the Overlord (the account `gh` is signed in as) committed, opened a pull request or opened an issue there in the last 30 days; bots (GitHub's bot accounts, any `[bot]` name, a name whose last word is `bot` or `robot` such as `deps-bot`, and agent accounts such as `claude` and `cursoragent`; a name that only ends in those letters stays a person) and fork-history authors with nothing recent do not count.
It lists those contributors with login and avatar, every open issue with assignees and labels, every open and draft pull request with the files it changes, and the branches anyone but the Overlord pushed in the last 14 days with author, login, age and the pull request each heads.
`--brief` reads the area from the brief's Task and Acceptance criteria sections, or from the whole brief but its Constraints when it has neither (paths with a slash that name a file or a folder the checkout has, and bare file names matched by name; Constraints, which name other goblins' files, are never read) and `--files` adds paths, naming any it ignores as not repository paths; a pull request's files or a branch GitHub cannot read is named under "Not read" rather than failing the report; the report then names every pull request and branch that changes a file in the area (a folder covers what is under it) and every open issue that names an area path or whose title the brief largely restates (at least three of its significant words and 60% of them).
`--json` is the same report with avatar URLs; issue bodies are read for matching and never printed

`cfo tickets <project> --allow-public-tickets`

Lets the supervisor keep tickets in the project's repository although it is public, where every issue is public; asked once per repository and recorded in the state directory.
Tickets themselves need no command: in a collaborative repository `cfo serve` keeps a GitHub issue for each task and is its only writer, so you never open, edit or close one, and no goblin does.
It opens the issue when the task is queued (or claims the issues the task's brief or backlog row names: by URL or as "issue #N" or "issues #N and #M" in its Task and Acceptance criteria, and by a bare "#N" that opens a line of its Task, which a pull request number in a sentence never does, every one GitHub says is an open issue; one named in words that it cannot claim is said on the board, a listed number that is no open issue is passed over, and only when it can claim none does it open an issue instead), except for work that was already queued when it first kept tickets, which gets its ticket when it starts so an old backlog is not a burst of issues, and moves it from the phase the board shows: `cfo: queued`, `cfo: in progress` with `goblin: <harness>` and the goblin's id in the body, `cfo: pr open` with the pull request linked, `cfo: paused`, `cfo: blocked` (saying only "waiting on a decision" or "stopped on a failure", never the question), then closed as completed on the merge with a comment naming the pull request, or as not planned when the task is stopped or finishes without a merge.
Before a not-planned close the supervisor asks GitHub about every pull request the ticket holds: one that merged, though the board lost it, closes the ticket as completed with that pull request named, and while one is still open the ticket waits and is asked again each hour.
A ticket holds every pull request of its task, listed in the body of an issue cfo opened, and only pull requests of its own repository: one a goblin reported from another is left out, and the board's Issues line says so.
Once a ticket's issue exists the supervisor names it, or every issue the task claimed, in the goblin's `state/tasktmp/<id>/ticket.md`, and every ship goblin's first instruction tells it to read that file before it opens a pull request and to write "Part of #N" in the pull request's body, so GitHub links the issue and each pull request both ways.
A claimed issue keeps its author's title and body, carries its state in one comment of its own edited in place, is closed on the merge, each claimed issue of the task with its own comment, and is released open rather than closed when its task stops unmerged.
Every issue a task opens or claims is assigned to the Overlord's account, the one `gh` is signed in as, and a claimed issue is unassigned when it is released.
A claim never takes an issue someone else has: one assigned to another account, or one with a `cfo:` state label that is not assigned to the Overlord, is left alone, the board says why, and the task gets an issue of its own when it can claim none.
So a second person running Code Goblins in the same repository sees each of this fleet's tickets assigned to the Overlord, its fleet never claims one, and its `cfo spawn` stops when a brief names one.
A ticket carries the title, the state, who is on it and links, and the reason you gave `cfo spawn --overlap-ok` as one "Started beside other work" line (in the body of an issue cfo opened, in the status comment of one it claimed).
The body of an issue cfo opened also says what the task changes and where: a "What" line with the brief's `## Ticket` section, the two or three sentences you write there for teammates and the only words of a brief that reach GitHub, joined on one line and cut at 600 characters, and an "Area" line with the repository paths its Task and Acceptance criteria name that the project's checkout has, the paths `cfo tickets --brief` reads less any the checkout lacks, so other fleets' spawn checks see the ticket by file.
Never anything else of the brief, a path on this machine, a secret or a note; its title is the one the task was queued or dispatched under (the backlog row's or the task record's), cut at a word to 100 characters and without a harness named at its end, which its `goblin:` label already says, or the task's id, never the board's own title, which can come from the brief's first line.
Once the issue is open it keeps that title, cut the same way, so a backlog row the CFO rewrites later, or a respawn copies from one, never renames it, and only `cfo title` changes it, closed or open; an issue opened under the task's bare id takes the task's title once it has one.
A ticket whose task has left the board (a finished task leaves it after a week or twenty newer ones) is still closed by its pull requests: as completed once one merged, or as not planned once every one closed unmerged, asked of GitHub once an hour, and one whose task is gone from the fleet with no pull request is closed as no longer in the fleet, once the task has been off the board for ten minutes.
A project with no GitHub repository has no tickets and raises no line.
It writes only when the ticket's state, pull request, harness, title or accepted overlap changes, and a new state only once it has held ten minutes, so a task that flips between states, such as blocked on a question answered at once, writes nothing until one stands, while a close is written at once; before it changes an issue's labels it reads them, removes only the labels it wrote and still finds there, and adds each it wants that is missing, so a label another fleet or a teammate removed comes back and theirs are never removed; whether a repository is collaborative is read once an hour in one GraphQL round; after a 403 or 429 the repository's tickets wait an hour; and the board's Issues line says when tickets wait, for that or for the public-repository consent.
The board shows each task's ticket number on its card, opening the issue, with the avatar of each teammate whose open pull request, branch or issue meets a live goblin's branch (from the ten-minute overlap read); a goblin's panel shows those of its project's people, as that hourly read found them, who committed to its default branch or opened a pull request, with their GitHub avatars

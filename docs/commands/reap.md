# cfo reap

`cfo reap [--dry-run] [--apply] [--force <pid\|task-id>]`

Find the fleet resources nothing else notices and retire them: a harness process whose pane or native terminal host is gone (unsupervised, invisible to `herdr agent list`, still spending tokens), a dev server left running in a worktree with no live evidence of its goblin (no pane holding an agent working there and, for a native goblin, no live host running its terminal, whatever the status log says: a task that never reported a terminal verb is reported and held, and a finished goblin's server is deliberately not reported while a live agent is still working in its worktree, which is the rule `cfo cleanup` already follows when it refuses to return a worktree whose pane still holds an agent), an orphaned worktree, task record or status log, and the empty directory a dead task leaves among the worktrees, which is not a worktree at all: the project does not register it.
A harness process is placed by where its program runs from, its ancestry and its environment, never by its image name, so the desktop applications (Claude Desktop, the Codex app and SIQshift, with everything they start, and a harness run from the first two's own folders, `AppData\Roaming\Claude\claude-code` and `AppData\Local\OpenAI\Codex`, whatever started it and whether or not that still runs), the agents of a `no-mistakes` round (under the daemon, or carrying the `NO_MISTAKES_GATE` it gives each one, which an agent keeps when the process that started it exits), the sessions the Overlord starts himself in Windows Terminal or a shell opened from Explorer (outside any `cfo` process), and the native messaging hosts of his browser (a `claude.exe` run as `--chrome-native-host` and nothing else, and whatever a browser's `cmd.exe` launcher starts on its `chrome.nativeMessaging` pipes) are not reported.
A goblin's harness with no terminal left is reported still, whatever its arguments name.
Whose a process is, the sweep asks where the janitor's process sweep and `cfo process-plan` ask it, by the one rule a terminal's teardown ends its own by.
A process that carries a mark a host of a running terminal of this home gave it (`state\hosts\<id>.proofs`), that works in that terminal's task's folders or runs a program from them, or whose parent is that terminal's own, is that terminal's and never an orphan, though its chain of parents stops short of the host, as it does where Git Bash runs `env` or `timeout` by replacing its own Windows process.
So a goblin's own tests are never its orphans, and the stand-in harness a goblin's test starts in a terminal of its own, which carries no mark of the goblin's terminal, is the goblin's by the task's folders it runs from and by its parents.
A harness that carries no mark of a running terminal, works in no running task's folders and has no parent that is a running terminal's own is an orphan still, and wakes you once.
The sweep reads the machine twice: its list of processes, which costs a subprocess and on a loaded machine is seconds old before anything else is read, and then, in one pass, which of those processes still run and whose each is.
A listed process is a finding only when the second reading still finds it by its pid and its start.
One that ended between the two is named in a note and is no finding, since a test's stand-in harness lasts about ten seconds.
A second reading that fails refuses the sweep, which is recorded as a failed sweep and raises no wake.
Worktrees are looked for in the home's `worktrees` folder and, for tasks an older build spawned, under the `.worktrees` folder of the home itself, every project a task record names and every checkout under the projects root; outside the home, a folder there counts only when this home's records name it, as a task's worktree or extra one, or as `gb-<id>` for a task this home holds a record, status log, outcome or archive of, so a worktree you made yourself, or another home's goblin's in the same checkout, is never reported, whatever the projects root says.
A goblin's extra worktree is that goblin's when its record lists it (`cfo worktree add`), or for an older build's, `gb-<id>-<suffix>` in the same checkout made after the goblin's own, for as long as its pane holds an agent or its native terminal's host runs, and is reported under its own name, held on the goblin's task, once it does not, so acting on it returns that directory alone.
A stand-in harness a test fixture runs, under a Herdr server of a session other than the fleet's, belongs to whoever works in the directory that server was started from: the goblin whose worktree holds it, or an agent or gate agent working in that worktree, or, outside every worktree, at or above that directory, never one working below it, so a fixture started from a project's main checkout is not kept by the goblins in its worktrees.
It is reported only once nothing live works there, against the goblin whose worktree that is.
A `cfo host` run with a `--state` other than this home's is a scratch CFO home some goblin's test or proof set up, and its harness is that goblin's fixture in the same way, tied by where the host was started, its `--state` or `--dir`, or the goblin's Claude Code scratchpad (`%TEMP%\claude\<worktree slug>`) holding them; a scratch home tied to no goblin is never reported as this fleet's orphan.
A program run from a goblin's Go temporary directory (its scratch folder, `$CFO_HOME\scratch\<task id>`, or `%LOCALAPPDATA%\cfo\gotmp\<fleet>\<task id>` for a goblin an older build spawned), such as a test binary serving as a native terminal host or the stand-in harness it runs, belongs to the task that path names in the same way only when it also runs from that task's worktree (or extra worktree), its task temporary directory, its scratch folder or its Claude Code scratchpad: skipped while that goblin lives, reported against it once it is gone.
The path alone names no owner, because the shared no-mistakes daemon builds every goblin's gate tests under the Go temporary directory of whichever goblin started it, so such a program nothing else places is held as unidentified, never killed by a sweep.
The tie runs only through such a server, host or Go temporary directory: a harness still running in a live goblin's worktree with no pane of its own is reported as an orphan, because that is what one left behind by a Herdr crash looks like.
Reporting is the default.
`--apply` acts on every finding it is not holding and **never ends a process**: everything else it does is recoverable, so a kill is authorised only by naming that pid with `--force`, and tidying a status log can never take a dev server with it.
A forced kill ends the process and everything under it but a machine service, Docker Desktop with what it runs, the no-mistakes daemon with its gate agents or the Scrawl server that keeps every goblin's review page, which serves the whole machine and is left running, as every teardown of a goblin leaves it.
It also never removes a worktree with uncommitted or unpushed work, or one no task owns that a live session may still be using, by the janitor's rule and with its reason, and never reaps a task that has not finished; `--force` names one pid or one task id and may be repeated, and every refusal answers only to its own key: a pid speaks for that process, a task id says that task is over, and neither speaks for the other, so a finding held for two reasons needs both answered and its HELD line says which keys to name; where a refusal answers to a key that line does not ask you to name, it also says that the rest is evidence to resolve rather than override.
Some refusals answer to no `--force` at all, the uncommitted or unpushed work gate and the live session's among them.
The watcher sweeps on its own timer and the session-start digest prints the result, so an orphan reaches you without your asking.
It wakes you only for a running finding (a harness or a dev server) it has not told you about, its holds included, never again for one it reported, and never for a worktree, record or status log coming or going beside it.
A fleet harness (one launched with the fleet's flag, or proven to run in one of this home's terminals) and a dev server are each told once for each process.
A harness nothing ties to the fleet, held as unidentified, is told once for its shape (where it runs from, the program that started it and why it is held), however many processes of that shape come and go.
What you were told is kept while a finding is away and forgotten a day after a sweep last found it, and `cfo reap` run by hand keeps it

## Reporting surface

- Plain chat is the default.
  A yes-or-no decision, a status answer, or a single recommendation goes in the conversation, never in an artifact.
- When several options, trade-offs, a structured report, a plan, or a comparison need the Supreme Overlord's eyes, load the `lavish` skill (`~/.agents/skills/lavish/`), write the page, and publish it with `cfo review --id <stable-id> --title "<what to look at>" --lavish <html-file>`: the supervisor polls the page and his feedback reaches you as a `review` wake, so you never hold your turn on `lavish-axi poll`.
- `lavish-axi` is presentation-only.
  Only pages named by their files (`cfo notify --lavish` and `cfo review --lavish <html-file>`), pages found by their Scrawl links in lavish-axi's state (`cfo review --lavish <link>` and `cfo present --kind review --watch`), and the supervisor's polls of them use it, so when it is missing, below its floor, or not the Code Goblins build (the upstream package) you say visual review is unavailable once, deliver the same content as text, and keep working; a page wait or a page review is refused and asks in text instead.
  Nothing else waits on it.
- The monitor watches for a goblin's own `lavish-axi poll`: one running in a goblin's worktree, or under a process that runs in one, that `cfo` did not start, wakes you once per poll with a `review` wake.
  For a live goblin it says what to tell it: stop the poll and wait with `cfo notify <id> --waiting-on overlord "<why>" --lavish <page>`.
  For a retired goblin, whose status log is all that is left, read the page's open questions, put them to the Overlord, and stop the poll.
## User decisions on the board

The registered primary CFO in any supported harness (Claude Code, Codex, Pi) must publish deliberate user questions with `cfo question --id <stable-id> --text "<question>" --option "<choice>" --recommend "<exact-choice>"`.
Repeat `--option` for actual choices; omit `--recommend` when no choice is recommended.
When the question puts a goblin's decision to him, add `--for <task>`: while it waits, that goblin's waits on him must declare whether they are this decision, and one it declares with `cfo notify --follows <this question's ID>` is hidden while the question waits and closed by its answer, so he sees one card, the decision.
When it comes with a message he sends himself, such as an email, add `--message-file <file>` in the form `cfo auth request` takes: his card shows it with Copy.
While [AFK mode](afk.md#afk-mode) is on `cfo question` refuses: nothing is asked of him then.
Write every question to the Overlord, the CFO's `--text` and a goblin's `--blocked` alike, to be read rather than scanned: lead with one short sentence that is the actual question, put the details on lines of their own that start with `- ` (a real line break, such as `` `n `` in PowerShell), and wrap only the verdict or the blocking item in `**two asterisks**`, never the whole question.
The Command Center shows it as body text: a blank line starts a paragraph, a `- ` line is a bullet, `**text**` is bold, and anything else, markup included, is shown exactly as written.
Other always accepts a written answer, and no answer is selected automatically.
Run publication from the registered primary session's shell and reuse the same ID/content for an uncertain retry.
Everything that speaks for the CFO on the board (`cfo question`, `cfo review` without `--task` and its `--withdraw`, `--clear`, `cfo deliver` without `--task`, and `cfo answer`) reaches the supervisor only over its pipe, which proves the sender is the registered CFO process, so it needs `cfo serve` running and fails with `start cfo serve` otherwise; nothing falls back to a file.
A goblin's own items still go through the inboxes and always show as that goblin's: an item in an inbox that claims to be the CFO's is refused and named on the board, whatever identity it carries.
This closes the file inbox path, not the same-user boundary: a process of this Windows user can still spoof another goblin's items, including withdrawing them, the CFO's `cfo present` notices without `--task`, text typed into a goblin's terminal (a `CFO:` line included), the wake queue and status files, `state/.supervisor.json` while `cfo serve` is stopped, AFK mode's switch and log (`state/afk.json`, `state/afk.audit`), anything run as a descendant of the CFO's harness, and the CFO process itself, which it can debug or inject into.
The board sends the durable answer to that same verified CFO as an ordinary message, so continue independent supervision or finish the turn while waiting.
Answers he gives to several of your questions in one go arrive as one message, which says how many there are and lists each in the order he gave them, as `[1/4] User answer to CFO question <id>.
Question: <text> Answer: <answer>`: act on every one of them.
He can change any answer at any time, whoever gave it, from the question's card in History: the change reaches whoever acts on the answer once, as `The Overlord changed ...
Was: <old>.
Now: <new>.`, the goblin that asked, or you for your own question and for a goblin that restarted or ended.
When it reaches you, undo or redo what the first answer started, and when that cannot be undone, such as a merge, carry out the new answer as a new instruction.
Do not also invoke a native question tool for this decision: an ordinary message typed into your terminal cannot answer a correlated Codex or Pi native prompt.
In Claude Code the pre-tool hook enforces this: the registered primary CFO's `AskUserQuestion` is refused with a pointer to `cfo question` and `cfo run-request`, because a native selector holds the whole turn, shows only in the CFO's terminal and never reaches the Command Center, so supervision stops while it waits.
A goblin's blocked question, in the form the [cfo notify reference](../commands/notify.md) gives, is the CFO's question to answer.
It never enters the Overlord's waiting count, alerts him or opens the Command Center; once answered it appears in History.
Publish the decision that needs him with `cfo question` from your own registered process.
An item addressed to him has one visible signal, **Open Command Center** and its count, and opens only when he chooses it.
Windows notifications require a hidden tab or minimized window, not merely an unfocused visible window.
After ten minutes of unanswered blocked or failed questions for the CFO, or questions a goblin asked in prose (`goblin_asks`) and nobody acked, one notice per durable stretch gives their count and oldest age and opens the CFO's terminal; those questions stay the CFO's.
When the choice is visual, such as mockups, brief the goblin to add `--image <path>` once for each choice, in order, so the Overlord picks by picture; the images must be PNG, JPEG, GIF or WebP files inside the goblin's worktree, task scratch or data directory.
For something the Overlord should look at without blocking the goblin, brief it to run `cfo review --id <stable-id> --task <its id> --title "<what to look at>" [--image <path>]... [--lavish <url|html-file>]` from its own pane or native terminal (while [AFK mode](afk.md#afk-mode) is on, one with a page is instead that goblin's question to you): the item stays in the Command Center until he clears it, the goblin withdraws it with `--withdraw "<reason>"`, or the goblin is cleaned up, whatever the goblin reports meanwhile, done included, and its images are copied so they outlive the worktree.
Clear a stale item yourself, such as one a retired goblin left, with `cfo review --clear <id> --reason "<why>"`; the clear is audited in `state/reviews.audit`.
A page whose review session has ended, whether he or an agent ended it, is refused by its link or by its HTML file, recording nothing, with a line naming `--reopen`, since its card would open Scrawl's "Session ended" (the Overlord met one on 2026-10-17); add `--reopen` to open it again with lavish-axi's own `--reopen` only when he asked for another look, under a new `--id`, since publishing an item that has closed again is refused rather than reported published with no card shown.
A page named by its HTML file, or by a Scrawl link whose page lavish-axi serves, is polled by the supervisor, so his answer on it (Send & End) reaches the goblin in its own terminal, reaches you as a `review` wake saying the goblin has it (relay it only when the wake says the goblin could not take it), and the item closes as answered by him on its page, which the board shows with the same check as an answer sent from its card; what he sends there without ending the review is a revision the goblin gets the same way, the page tells him the next version replaces it, and the goblin's next `--waiting-on overlord --lavish` of the same file replaces the item in place; a review window he closed or that disconnected ends nothing, since the supervisor keeps polling until he answers or ends the review there, so never ask him whether to reopen it.
Nor does anything that closes the item: the goblin's withdraw or his dismissal of the card leaves the page watched, and what he writes there later reaches the goblin as a note on its page.
A sweep at `cfo serve` start and every ten minutes reads every Scrawl session without taking anything, delivers feedback left on any fleet task's page nothing watches (to the goblin while it runs, otherwise to you as a `review` wake naming the task, to act on yourself), and ends a retired goblin's open page with a reply saying why, so you never poll a page before retiring its goblin.
A goblin's question and its open page item are separate, whatever the question is about: his answer on the page closes only the page, and your `cfo answer` closes the question and only the waits the goblin declared to follow it with `--follows`, never the goblin's page or any other wait on him, such as a sign-in only he can clear; only a page AFK mode asked of you as the goblin's question closes with your answer, since that question is the page.
For the same reason his answer on that page, Send & End or a pick of an option it declares, answers that question: the supervisor polls the page until the review on it settles, so the question's card leaves his Command Center the moment he sends, its notify reads answered, and the goblin gets his words as from any page; once you have answered it, what he sends there is a note the goblin gets.
His board answer on a goblin's item or wait goes to the goblin and also to you, as a `review` notice that asks nothing.
To hand the Overlord a file, such as a picture or a PDF report, run `cfo deliver --id <stable-id> --title "<what it is>" --file <path> [--download]` (a goblin adds `--task <its id>` and delivers only from its own worktree, task scratch or data directory): it makes a Scrawl page that shows the file, a picture inline, a PDF page by page and plain text as text, and presents it in the Command Center as a review item, so what he writes on the page reaches whoever delivered it as a `review` wake, the way `cfo review --lavish` does.
Add `--download` only for a generated asset or a file he asked to keep: the page then offers it to download, and a picture only to look at has none.
A file the page cannot show, such as HTML, SVG or an archive, is refused without it.
`cfo drain` then shows that notify as answered on the board and acks it without `--ack-blocking`; answer a goblin in one place, and ack a question you answered with `cfo send` promptly so the board retires its copy.
Answer a goblin's question yourself with `cfo answer <wake-seq> --option <choice> [--note "<text>"]` rather than `cfo send` plus `--ack-blocking`: the goblin receives the same `CFO:` line, the notify retires through an ordinary drain, and the board shows a check on the option you chose with "Answered by the CFO"; a question you answered with `cfo send` and retired with `--ack-blocking` also closes as answered, reading "The CFO answered it" with the check, but marks no option.
See the [cfo answer reference](../commands/answer.md) for paused retention, queued delivery and command output.
A question whose notify could not show it on the board (the notify printed why) is answered the same way: after 30 seconds `cfo answer` sends your choice straight to the goblin that asked, refusing a goblin that restarted since, so never fall back to `cfo send` for it.
A question you already answered another way (the goblin has your decision and its notify is acknowledged or answered) shows no chosen option on the Command Center until it is recorded; record it with `cfo answer <question-id> --option <choice> --record-only`, naming it by its ID `notify-<task>-<sequence>`, which records the choice on the board and sends the goblin nothing, and refuses a notify still waiting unanswered or a question the Overlord is answering.
When the Overlord answered a question somewhere else, such as in chat, record his answer with `--in <where>` added (`cfo answer herdr-strays-20260929 --option "Stop them" --record-only --in chat`): the card closes as his answer there, recorded by you, and your own `cfo question` takes only this form, since only he answers it.
He can also dismiss a question he answered elsewhere or no longer needs from its card; you are told, and a goblin's notify still waits for you to resolve.
Other worker alerts stay in the CFO wake queue until the CFO deliberately escalates a real user decision.
When you need the Overlord to run a command you cannot run yourself (a classifier refusal, a step that needs administrator rights, or credentials only he holds), create a run item instead of pasting the command into chat: write the exact command to a file and run `cfo run-request --id <stable-id> --title "<why>" --shell powershell|pwsh|bash [--admin] [--cwd <dir>] --command-file <path>` from verified primary context.
He runs it with one click from the Command Center, in exactly that shell and, for `--admin`, elevated once he confirms Windows' prompt; it runs in a terminal drawn on its card, where he types into it, so a sign-in or anything else that needs a console works there, and no window opens.
When it exits the card completes by itself, and its exit code and the end of what its terminal showed come back to you as his answer.
The request travels over a named pipe only the current Windows user can open, and only to the process that holds this home's watch lock: a pipe of that name served by anything else never receives it, and a supervisor that finds the name already taken serves no run requests and says so on the board.
Never put a secret in a run command or request one that prints a secret, or asks him to type one where it is shown: the output is stored on the board.
When the command comes with a message he sends himself, add `--message-file <path>` in the form `cfo auth request` takes: his card shows it with Copy.
To take back an item he has not run, such as one whose command went stale, run `cfo run-request --withdraw <id> --reason "<why>"`: it leaves the Command Center with the reason, `state/runs.audit` records it, and Run on it is refused; to replace it, withdraw it and publish the new command under a new ID.
`cfo review --clear` does not reach a run item.

For a nonblocking walkthrough or review, prefer a Scrawl page, the Overlord's name for the review page `lavish-axi` serves (`lavish-axi <file> --no-open`), then report the returned safe URL with `cfo present --id <stable-id> --kind browser|review --url <safe-url> [--watch "<what to watch>"]` from verified primary context.
A goblin reports its own with `--task <its id>` from its own pane or native terminal, which needs no native hook; the tailnet URL `lavish-axi` returns is accepted as it is, so it opens on the Overlord's phone too, and a refusal names the rule the URL broke.
Refresh only while actually live and report `--state ended` when finished.
A `--kind review` with `--watch` waits on him, so it is published as a review item under the same ID, titled by that line and polled on its page, which his Send and End there closes; its `--state ended` withdraws the item.
Viewing choices never pause autonomous work, and opening a URL does not mirror browser control.
